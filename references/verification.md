# 驗證方法論

分析結果可信與否，取決於**驗證方法本身可不可信**。工具鏈自己的假設若錯了，
所有 PASS 都沒有意義。

---

## 驗證分層

### 工具自動做的檢查

讀 netlist、`.DSN` 階層對帳、元件模型的基本檢查都由 `init`／`audit` 自動執行，
不過就硬停。檢查項目與設計理由見 `docs/設計說明.md`。回答時只需要知道：

- 稽核報告第 [0] 段沒過 = 工具讀 netlist 出錯，**任何結果都先不要相信**。
- `init` 對帳沒過就停下，不會產出半套結果。PADS 改名（`X#####`）對帳時會列
  對照表，那是改名不是接錯。
- 元件模型通過工具檢查，只代表腳號都存在，**不代表封裝或功能解讀正確**——
  交付時列進人工複驗。沒填 `verified_against` 的模型工具拒絕載入，**不要為了
  讓追跡跑通而繞過它**：追跡停在某顆 IC，是「這裡還沒查證」的正確表現。

### 第 2 層：內容斷言

把文件裡每一條可機械驗證的主張寫成 `assertions`。可用的 kind：

| kind | 驗什麼 |
|---|---|
| `count_pn` | 某料號共幾顆 |
| `pin_net` | 某顆某腳接到哪條網路 |
| `pin_net_seq` | 連續腳位對連續網路（`{i}` / `{i-1}` 代入） |
| `bom_value` | BOM 的值含某字串（電阻值等） |
| `not_stuffed` | 這幾顆是 DNI |
| `net_pin_count` | 某網路掛幾支腳 |
| `net_count` | 符合 pattern 的網路有幾條 |
| `single_pin_nets` | 懸空網路總數（可加 `all_from` 限定來源料號） |
| `i2c_addr` | 由位址腳反推的 I2C 位址 |
| `net_exists` | 某網路存在 |

加上 `role_rules` 把 `U<n>03` 這種通則展開逐顆比對。

**首次執行的 FAIL 就是文件的錯。** 改文件，不要改斷言遷就；改完後把斷言改成
驗證「更正後的事實」，並在文件裡誠實記錄「首次 N 條中 M 條 FAIL」——
之後重跑全 PASS 是「已修正」的結果，不是「首次就全對」。

## 跨板對接：直通或線束

netlist 沒有跨板連線，對接是**推論**。前提是**板子都已在實體世界接過、可以用**，
所以工具不判斷「有沒有接」，只判斷「怎麼接」；不考慮 footprint 畫錯、零件庫
編號錯這類情形。

- **兩側系列不同 → 公母直接對插 → 直通。** 兩側電壓命名不同（`3P4V_C` 對
  `3P3V_C_VDD_X`）是常態，不代表接錯；net 名對不上多半是兩側命名習慣不同，
  補 `net_normalize`，不是放寬門檻。
- **兩側同系列 → 插不起來，中間必有線束 → 照訊號名稱對應。** 名稱對不上時
  接法不在 netlist 裡，請使用者提供 `mate_map`。
- **兩側都有多組候選（Primary/Redundant）→ netlist 分不出誰插誰，問人。**

⚠️ **扇出**：一片板插到 N 個同型槽位時，N 片在工具裡共用**一份** netlist。
跨板進入那片板之後若再從同一顆連接器走回其他槽位，N 個槽位會看起來互相接通。

判定門檻見 `docs/設計說明.md`。

## 結構上驗不到的四類

工具再怎麼加也驗不到這些。`REVIEW.md` 會固定列出來。

| 類別 | 例子 | 為什麼驗不到 | 怎麼補 |
|---|---|---|---|
| **因果推論** | 「這個 RC 造成約 4 ms 延遲」「這個拓樸是為了匹配路徑長度」 | netlist 不含設計意圖 | 實測，或問設計者 |
| **實體板狀態** | rework、飛線、換料 | `.asc` 是設計，不是那一片板 | 查該片的 rework 紀錄 |
| **layout 決定的量** | 阻抗、插入損耗、耦合、串音、footprint 方位 | 不在 netlist 裡 | layout 檔或實測 |
| **專案外資料** | 自製 IC 的封裝腳位表、線束圖 | 檔案根本不在手上 | 向外取得 |

⚠️ **第二、三類最容易被忽略**：即使改版「電路設計完全沒變」，只要 layout 或
材料變了，量測數值就不能跨版本沿用；而 netlist 推導的結論則可以。
交付時要把這條界線講清楚。

## 交付時要說的話

不要用「全部通過」交付。要分開講：

> **A 段（工具驗得到，已通過）**：parser 自我驗證、N 條內容斷言、命名規則展開、
> DNI 對帳、懸空網路。
>
> **B 段（工具驗不到，需要你人工確認）**：腳位模型是否真的翻過 datasheet、
> 工具定不了的對接（`mate:ambiguous`）、rework 紀錄、線束、BOM 變體、文件裡的因果推論。

`ndd.py review` 會把這兩段寫成 `REVIEW.md`；`ndd.py coverage` 給 per-MPN 的
三源覆蓋表。

### 正式 trace 與 topology hint 不可互換

`signal_chain.csv` 只含**已驗證的 signal_transfer 邊**，可作架構結論。
`topology_hint.csv` 是控制、狀態、參數與未知邊界的**功能說明**——
它不是連通關係，**永不得作為下一跳**。
